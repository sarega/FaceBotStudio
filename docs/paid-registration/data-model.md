# Phase 0 — Data model and concurrency

Proposed TypeScript-first contract. Add paid-specific DTOs and transactional commands to `AppDatabase`; implement equivalent invariants in both adapters. Table names remain provisional.

| Record | Fields and constraints |
|---|---|
| Event and paid settings | Nullable `events.registration_mode` with CHECK over `free, paid_registration, direct_ticketing`. NULL retains existing mode/visibility/feature-flag routing, including external ticket links and staff-only direct ticketing. `paid_event_settings` keyed by event, stores positive capacity and hold duration, optional UTC cutoff, pricing/form version, registration availability and published configuration. No implicit 48-hour default. |
| `paid_categories` | Event-scoped stable ID, label, enabled, positive `unit_minor`, optional positive quota. Composite PK `(event_id,id)`. Retire categories with history via disable. Form definitions at event scope have stable field keys, scope, type, bounds, options and required flag. |
| `paid_bookings` | Opaque ID, random display reference, event ID, owner organization ID, optional organizer profile ID, verified owner customer ID, primary contact and answers, status, payment status, currency, `total_due_minor`, immutable pricing/version and private receiver snapshot, source, due time, nullable review/escalation timestamps, optimistic version, created/updated/confirmed timestamps. Reference unique. Enforce event/tenant pair and organizer/tenant pair via composite FKs with corresponding parent uniqueness. Restrict deletion of referenced event/organization/organizer and control tenant reassignment. |
| `paid_attendees` | Opaque ID, event/booking/category IDs with composite same-event FKs, names, optional contact, immutable unit price/category label snapshot, validated answers/form version, active or cancelled state, check-in timestamps/actor. Active and checked-in attendees occupy one unit each while booking is held or confirmed. Enforce unique ordinal within booking, audit corrections, no cascading loss of financial history. |
| `paid_payment_attempts` | ID, booking FK, sequence unique within booking, method, status, immutable claim amount/time/reference, separate observed amount/time/currency/reference/receiver and source, reviewed actor/time/reason. `paid_bookings.total_due_minor` is the single obligation. A partial unique index on booking ID for an accepted settlement prevents double settlement. Keep observed amount and accepted settlement distinct. Never sum claimed proofs as cash. |
| `paid_proofs` | Attempt FK, immutable private object key, verified MIME/byte length, SHA-256, canonical intake time, uploader kind and ID, optional retention/deletion marker. One immutable original per proof attempt. Unique storage key and indexed checksum. Restrict access via booking/event ownership. Persist checksum after object deletion only according to retention policy. |
| `paid_credentials` | Event/booking/attendee scoped FKs, attendee ID, issuance version, unique opaque public handle, issued and revoked timestamps, signing key version. Partial unique index for one live credential per attendee. Signed QR carries purpose, handle and key version. Store no bearer URL in logs or outbox. |
| `paid_command_keys` and `paid_audit_events` | Unique command scope `(principal,event,operation,key)`, canonical request digest, minimal result binding and created time. Audit append-only with event, booking, actor, source, action, old/new states, reason, time, request ID. Store no raw slip, secret or full payment identifier in audit payload. |
| `notification_deliveries` | Reuse existing outbox. Insert minimal booking/credential references with stable semantic delivery keys in the same transaction as the transition. Resolve contact and authorized render links at delivery, with event/state recheck. |

Use THB satang integer arithmetic for MVP, safe integer bounds on all calculations and DB CHECKs for money, state values and version. PostgreSQL BIGINT needs explicit checked mapping to TypeScript number; SQLite INTEGER uses equivalent bounds. Use UTC epoch milliseconds or canonical UTC timestamps consistently across adapters; do not lexically compare mixed SQLite formats. Enforce sum of active attendee snapshots equals due, currency/receiver equality, and confirmed requires one accepted exact settlement through the atomic commands. Index bookings by event/state/due and owner/event, attendees by event/category and booking, attempts by booking/review status, and audit by booking/time. Use a partial unique normalized trusted bank reference keyed by verified rail, receiver namespace and transaction ID, retained after refunds. Treat matching slip hashes and claim strings as flags. Search legacy verified references as additional review evidence. Cross-table atomic dedup is a rollout decision, since legacy writers never acquire a shared reference lock.

## State and transactions

- Open PostgreSQL transaction on one client, lock event row first, then booking and dependents. SQLite uses synchronous `transaction(...).immediate()` with foreign keys and bounded busy retry before rereading state. Use the same ordering for creation, expiry, proof intake, review, cancellation, reinstatement, settings, attendee edits and check-in. No network I/O under lock. Sample authoritative time after acquiring the lock.
- Create by verifying event availability and requested pricing version, checking replay, counting confirmed + live held units per event and category, and inserting the whole group, audit and command result. Hold deadline is the earlier of transaction time plus configured duration and optional cutoff. Reject a deadline at or before now. Keep the quote and receiver identifiers server-derived. Settings updates cannot lower capacity or quotas below occupancy.
- `awaiting_payment/unpaid` holds units until strictly before `due_at`. `verification_pending/proof_submitted` holds units until an explicit review action. DB-visible accepted intake before `due_at` pauses expiration. Stage valid bytes privately before intake; return success after commit. Delete unreferenced staged objects after a bounded recovery window, without deleting referenced objects on replay or after ambiguous commit.
- The expiry sweep conditionally changes due awaiting rows to `expired` and appends one audit event. Capacity reads ignore elapsed awaiting holds even if the sweep is late. Create and sweep share the lock. Use bounded batches and recover on startup. Review age triggers escalation, with no routine pending-proof release.
- Proposed rejection baseline uses only the unspent time at original due date. Approval or rejection requires current attempt/version. Rejection returns to awaiting if original due is still future, otherwise expires. A separately authorized extension may be offered subject to reviewed policy. Duplicate suspicion, under/overpayment and late evidence go to manual resolution. Keep any valid pending hold during investigation via the pending state plus exception flag, with escalation. `payment_exception` denotes an exception without an active hold. Policy review must set exception dispositions.
- Approve only if active hold, authorized reviewer, trusted verified amount exactly equals due, receiver/currency match snapshot, and reference/duplicate review passes. Staff recording without customer proof requires a still-live hold and trusted evidence. Atomically write verification, confirmation, one credential per attendee, audit and outbox. Approving the same command replays; other attempt/version yields conflict. A late transfer cannot recreate a hold. Explicit authorized reinstatement acquires the lock, rechecks all quotas and audits the reason before creating a new due window; payment approval is a separate validated transition.
- Cancellation/refund recording appends history and revokes eligible credentials in the same transaction. Keep original settlement and new refund record distinct. Scan resolves purpose, signature, event and attendee, then atomically checks current confirmed/verified status, active attendee and credential revocation before compare-and-set attendance. Concurrent scans produce one first check-in; replay reports already checked in. Cancellation after successful check-in requires a reviewed policy.

## Upgrade and rollback

Add a new numbered PostgreSQL migration after 039 (recheck tip on implementation). SQLite mirrors new DDL and conditional column/index initialization, using a serialized transaction and existing legacy initialization ordering. No historical booking conversion. Keep legacy tables readable and unchanged by paid transactions. Test fresh and upgraded databases, rerun migration, and assert legacy event routing and rows survive. Deploy additive schema before enabling writers, then enable for an eligible pilot event. Rollback is disabling new paid enrollment while continuing secured read/review/check-in and preserving balances and holds. Reverting to an older build after paid rows exist requires a drain or a compatible operational service. Leave schema and audit intact.
